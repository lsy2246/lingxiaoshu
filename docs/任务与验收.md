# 必做任务与操作验收

1. 从干净环境启动，记录已有错误、请求及根因，再修改代码。
2. 页面创建新任务，刷新后看板保留；任务、内容、组织和运行绑定正确。
3. 点开新任务，分别执行running、missing_authorization、failure和success；看板及详情正确反映后端状态，阻塞有原因。补充pending、waiting_approval、cancelled等状态用例；未知状态不能显示成功。
4. 工作台实际显示分镜、口播、音视频。模拟成功后视频与音频可播放。修改分镜/口播并保存，刷新和Ctrl+C重启服务后仍保留。
5. task-done展示film-1/v1/run-1；同内容出现新成片后仍保持原交付。不允许找不到原产物时回退最新版。可以扩展快照模型，解释历史内容和当前可编辑内容的关系。
6. task-unbound显示明确未绑定，不打开content-a；缺任务、缺媒体、接口失败均有可理解反馈。读详情不触发执行。
7. tenant-a请求task-foreign必须由后端拒绝；客户端传tenantId不能越权。任务记录/内容记录组织错配也要防护。
8. 在浏览器地址加 ?delayMs=1500，先点“视频制作”，立即点“历史成片交付”（只对前者增加延迟），返回看板或切换模拟身份时旧响应不能覆盖当前详情。需要接入页面并提供确定性延迟测试；单独展示辅助函数不算完成。
9. 每一项修复都有可重复步骤和必要测试。提交实际运行证据，不以截图替代代码。

## 自选加分

版本对比、轮询或事件更新、冲突检测、返回恢复位置、结构化日志、快捷键/可访问性；任选0–2项即可。可提出而不实现更长期的架构方案，明确哪些已经运行、哪些只是建议。

## 现场验收

评审者新建此前不存在的任务，自行操作闭环，然后注入接口失败、延迟或绑定缺失之一，请候选人现场定位并修复。具体追加故障不提前给出。录屏之外还会检查最终commit和代码。后台数据验证与真实浏览器操作均需通过。
